## Failure analysis

- **Fixed** missed 'eval-brief/eval-brief-b'. The 100 ms brief event can fall between the 250 ms fixed slots.
- **Global RGB** missed 6 of 9 observable events. Its 1.5% whole-frame gate and 1.5 s silence refresh did not react to sub-1% local text and low-contrast changes.
- **Local and hybrid** missed 'eval-background-motion/eval-motion-text' even though they sent 21 frames in that scene (21 outside labeled events). The unrelated moving object consumed the rolling 20-frame budget before the labeled event; this is a real budget/backpressure failure, not a labeling error.
- The hidden pause event is excluded from recall because the capture gap contains no input frame.

## How to read recall

Recall means **at least one delivered frame timestamp falls inside the event's labeled window**. It says nothing about whether a vision model or language model understood the event. Event labels and regions are used only after replay; they are never passed to a policy.

A send outside a labeled event is not automatically wrong: the event set is intentionally sparse and does not label every meaningful visual change. Treat it as a diagnostic, not a precision score.

## Notes

- Recall counts an event as captured when at least one delivered frame timestamp falls inside its labeled window. It does not measure whether a model understood the event.
- Event labels and regions are consumed only by the evaluator after replay. Sampling policies receive only the current sample and their own prior accepted sample.
- All strategies replay the same frame samples, timestamps, budget window, frame limit, minimum interval, and silence refresh.
- Events entirely inside a capture gap are reported separately and excluded from the recall denominator.
- Processing time is measured wall-clock time and varies between runs; sub-millisecond values are near timer resolution and should be read as relative diagnostics. Frame decisions and replay inputs are deterministic.
- The evaluation suite is held out from parameter selection.
