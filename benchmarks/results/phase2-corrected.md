# SemanticStream Phase 2 corrected replay — Bounded Context Buffer and Active Retrieval

Generated by `npm run benchmark`. This report is a real deterministic replay result, not a hand-written example.

## Configuration

- Samples: 96 × 54 RGBA at 30 fps
- Real-time budget: 20 frames / 5 s; minimum interval 125 ms; silence refresh 1500 ms
- Local policy: 2.5% per 8×8 block
- Buffer bounds: 3000 ms / 90 frames / 3.00 MB
- Retrieval budget: 6 frames and 2.00 MB per 5 s
- Combined real-time + retrieval budget: 26 frames and 4.00 MB per 5 s
- Selected cue interval: 500 ms

## Cue selection

Only the tuning suite selects the cue interval: maximize post-retrieval recall, then minimize retrieval frames and denials; the evaluation suite is held out.

## Cue vs oracle

- **C · Local + cue retrieval** uses only a real system signal: a real-time decision that failed the rolling budget. It requests the latest buffered frame with a 500 ms minimum spacing. It does not read event labels.
- **Oracle · local + label-timed retrieval** reads event midpoint labels and requests the corresponding frame. It is an **upper-bound experiment only**. It is not evidence that an agent can discover those events autonomously.

The cue strategy improves the held-out post-retrieval recall from 88.9% to 100.0% while adding 5 retrieval frames and 103.7 KB. The oracle reaches 100.0% with 9 retrieval frames, but it bypasses the production retrieval budget. It is headroom evidence, not a deployable result.

## Cache behavior

The buffer is bounded by age, byte count, and frame count. It stores owned RGBA copies, not Canvas references. Peak memory and evictions are per scene; the aggregate uses the maximum peak and the sum of evictions.

- No whole-video cache is created.
- A frame that was never captured (for example during a capture pause) cannot be recovered by retrieval. The hidden pause event remains unreachable.
- Requests for evicted, not-yet-captured, nonexistent, or wrong-session data return explicit statuses instead of empty success.

## Notes

- A is the fixed baseline. B is the Phase 1B adaptive local baseline. C uses a real-time budget-denial cue to request the latest buffered frame; it does not read event labels.
- The oracle strategy uses event midpoint labels to request a frame. It is an upper-bound experiment only, is not evidence of autonomous discovery, and bypasses the production retrieval budget.
- Retrieval requests are charged to a separate retrieval budget and to a combined real-time + retrieval budget. The buffer is bounded by age, bytes, and frames.
- Events with no captured input frame cannot be recovered from the buffer. Retrieval can only return frames that were actually stored and are still retained.
- Evidence coverage uses capture inside the labeled window. Deadline coverage requires delivery before the window closes. Budget auditing uses delivery time.
- Request and delivery timing uses the deterministic replay clock. Synchronous retrieval has zero simulated service time.
